# Images

Images are nice to have, not required. The editor wants stories with pictures when they're available, because they carry the homepage and the Facebook posts. A good story with no image still beats a weak story with one. When two leads are otherwise even, pick the one with the image.

Every image on the site needs permission and a credit, and goes through the media library. Never take an image from a Facebook Page, an X post, an organizer's site or an artist's publicity page just because it's public. Never use AI-generated images.

## Where to look, best first

1. **The media library.** `start_day.py` lists what's there. A licensed downtown, park or building photo already in the library may fit (`status: library` with its `media_id`). Check that its caption still makes sense for the new story.
2. **A press or media kit that grants use.** Some organizers publish a folder explicitly for media use, and some foundations publish media-usage terms. Confirm that the terms cover the specific file and what credit they require. A logo permission doesn't cover photographs.
3. **Openly licensed file photos.** Wikimedia Commons (public domain, CC0, CC BY, CC BY-SA), work by U.S. federal employees, and other repositories that state a license.
   - Read the license on the file's own page. Not every image on a government account is public domain, and state and local government work usually isn't.
   - Record the creator, capture date, source page, license and license link.
   - **CC BY-ND** can't be cropped, so use it as an uncropped body figure, not a cropped lead or card image.
   - **CC BY-SA** needs public attribution with source and license links, and adapted versions stay under CC BY-SA.
4. **Ask for permission.** When the right image belongs to an agency or organizer (a portrait, a flyer, an event photo), draft a short request with the contact from the source: what image, which story, how it will be credited, and a question about the capture date. Put the draft in `review.md`. **Don't send it.** The editor sends requests.
5. **Shoot it.** If an event in the core area happens today or tomorrow, note it as a photo opportunity for the editor: what, where, when.

## Saving a cleared image

Download the original file into the packet's `images/` folder with a descriptive name (`saints-peter-paul-exterior-2016.jpg`). Keep the original bytes: the media library strips metadata itself at import. Look at the picture before you describe it. Check what it actually shows and whether it shows the place the story is about.

## Caption, credit and alt text

- **Caption:** say what the photo shows, where, and when it was taken. End file photos with "File photo." For example: "Saints Peter and Paul Roman Catholic Church in Sandusky, photographed April 29, 2016. File photo."
- **Never let a file photo imply it shows the current event.** A 2016 church exterior illustrates a 2026 roof closure. It doesn't show roof damage, and the caption mustn't suggest it does.
- **Credit:** creator, source and license, such as "Nheyob / Wikimedia Commons / CC BY-SA 4.0". Put the source and license links in the story.
- **Alt text:** describe what the image shows, for the story's purpose. Keep it under 300 characters, don't start with "image of" or "photo of", and don't repeat the caption. Any text inside the image (a flyer, a schedule) also goes in the story body or caption.
- **Placement:** `lead` for the story's lead image, or `body` (an uncropped figure, for example under a no-derivatives license).
